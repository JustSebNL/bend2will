obey.

Run and supervise an ordinary program as a managed service on Windows, Linux and macOS.

// The two-line form — add to any Go program
func main() {
    return bend2will.Guard("myapp", os.Args...)
}

Overview

obey puts a thin supervisor in front of a program that knows nothing about service managers. It handles starting at boot, restarting on crash, and stopping cleanly — without the program having to change at all.

As a library

Two lines in your main(). Guard reads the usual flags, supervises the command line, and translates whatever the platform's service manager does into a clean start and stop.

As a CLI

The obey command installs, starts, stops, and removes services using whatever the host operating system provides.

Quick start

# See what a service would look like
obey show myapp --command /usr/bin/myapp --arguments --serve --port 5432

# Supervise a program in the foreground
obey shoo myapp /usr/bin/myapp --serve

# Install as a real service
obey bind myapp --command /usr/bin/myapp --enable --now

# Check its state
obey report myapp

# Stop and remove
obey terminate myapp
obey release myapp

How it works

obey detects the platform, connects to its service manager if there is one, and then supervises. On Windows the SCM owns the main thread; on Linux systemd watches the unit file; on macOS launchd manages the plist. In every case the supervisor loop is the same: start the child, wait for readiness, watch until exit, restart with backoff if configured.

Lifecycle

Starting → Running → (Stopping) → Stopped

When restart=true, an unexpected exit returns to Starting after a backoff delay. A clean exit (code 0) or a stop request ends the service.

bind alias: install

Install a service with the platform's service manager (SCM / systemd / launchd).

obey bind [options] [command [arguments...]]

Additional options

FlagDescription
-unit-dirDirectory to write the service definition into
-enableStart the service at boot
-nowStart the service immediately
-dry-runReport what would happen without changing anything

Examples

# Install a service
obey bind myapp --command /usr/bin/myapp --arguments "--serve"

# Install and start immediately
obey bind myapp --command /usr/bin/myapp --enable --now

# Preview without installing
obey bind myapp --command /usr/bin/myapp --dry-run

# Install to a custom directory
obey bind myapp --command /usr/bin/myapp --unit-dir /etc/systemd/system

portable

The portable edition: the same commands, installed per-user without root.

obey portable <command> [options]

Examples

obey portable bind myapp --command /usr/bin/myapp
obey portable serve myapp
obey portable report myapp
obey portable release myapp

Configuration

Configuration files use an INI-like format. A file may hold several services; the section name selects which one to load.

# a comment, or a ; comment
[myapp]
command = /usr/bin/myapp
args    = --serve --port 5432
restart = true
workdir = /var/lib/myapp
user    = myapp
env     = PORT=5432
env     = MODE=production
after   = network-online.target
Flags override file values, which override defaults. Precedence: flags > file > defaults.

Signals

Signalobey's response
SIGINT / Ctrl-CGraceful stop — same as stop command
SIGTERMGraceful stop
SIGKILLCannot be caught — process dies immediately
A second SIGINT or SIGTERM during shutdown shortens the wait but cannot make the shutdown ruder. The child is always given StopTimeout to exit before being killed.

Absorbing bend2will into another Go project

Clone the repo inside your project's tools/ dir and add a few lines:

cd your-project/tools
git clone https://github.com/bend2will/bend2will.git

Add to your go.mod:

replace github.com/bend2will/bend2will => ./tools/bend2will

Your main.go:

package main

import (
    "os"
    "github.com/bend2will/bend2will"
)

func main() {
    if err := bend2will.Guard("myapp", os.Args...); err != nil {
        bend2will.Fatal(err)
    }
}

Build it:

go build -o bin/myservice ./tools/bend2will/cmd/obey

The resulting binary is a standalone service wrapper. It accepts all the same flags as the obey CLI and can be installed, started, stopped, and removed as a real service.
